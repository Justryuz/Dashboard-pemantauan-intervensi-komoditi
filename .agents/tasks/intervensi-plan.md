## Keputusan (resolusi 4 dapatan MEDIUM)

1. **Anchor trigger (MEDIUM 1).** The mobilisation engine runs only if `supplyConfirm(mode, anchorSupplyRow).state === 'disahkan'`. Otherwise it returns `{dalam:[], luar:[], trigger:{ok:false, reason: state}}`. Paparan 4 then shows "PO terpilih tiada lebihan/kekurangan bekalan yang disahkan" plus the reason ("Menunggu pengesahan bekalan" / "Data stok lapuk" / "Tiada data bekalan"). The anchor flood banner renders independently of `trigger.ok`. Rationale: "zero surplus" and "confirmed surplus" were two rules; the B5.3 definition is the business rule, so T4 (Kangar) and T5 (Samarahan) must show the message with no lists. B13 7c for Samarahan/T5 asserts: banner present, message present, no lists, no exception.
2. **"Disahkan" wording (MEDIUM 2).** Paparan 3 suffixes become " + lebihan bekalan dikesan (data dummy)" and " + kekurangan bekalan dikesan (data dummy)". `disahkan` stays only as the internal `supplyConfirm.state` name. Delete `stockVerified` from B3.5. `stockVerification` is the single constant `'belum disahkan'` (remove `'disahkan (dummy)'`). Update B13 6b and AC-5 strings to match. Rationale: the UI must never claim stock is verified while Paparan 4 says "Belum disahkan".
3. **Tab click before settle (MEDIUM 3).** A manual click on the tab switches immediately, with no queue. Only the `#intervensi` hash at load waits for `Promise.allSettled([loadPromise, famaScenariosReady])` plus one `requestAnimationFrame`, with a 3000 ms safety cap after which the hash is applied anyway. A manual click before settle shows the P4 chip "Amaran cuaca/banjir AMS sedang dimuatkan", and `ivRefreshScenarios()` re-renders when the promise settles. Remove the "queued" sentence from B1. Rationale: the user can always navigate, and the old map is resized on return.
4. **Negative values (MEDIUM 4).** Any recommended price (`MaxFarmPrice`, `MinSell`, range ends) that is negative, zero or non-finite renders as "—" and its card shows the infeasible text. Margin %, margin impact (pp) and spread are signed and shown as computed with a minus sign; `NaN`/`Infinity` renders "—". `beli > jual` is accepted: the spread is shown negative and the field gets the warning "Harga Borong Beli melebihi Harga Borong Jual". So B13 step 8's "-3.00 pp" passes. Replace "Nothing negative is ever rendered" in B4.6.

NIT resolutions adopted (apply while coding): (5) price used = `ivPrice(po, commodity, 'Borong').actual` averaged over the PO districts; expected T1b numbers are about 15.29 RM/kg and gap about +0.62 at 30 hari. (6) Header and footer stay shared; `#downloadCsv` and `#downloadLogistik` are hidden while the new tab is active via `body[data-iv-tab=intervensi] #downloadCsv,body[data-iv-tab=intervensi] #downloadLogistik{display:none}`. (7) add `grade:null` to CommodityPrice with note "gred tidak tersedia dalam data sedia ada". (8) priority/mobilisation scores are normalised by the maximum inside the list's eligible set (B5.6). (9) pin Muse record dates: M01 11 Nov, M02 12 Nov, M03 13 Nov, M04 11 Nov, M05 13 Nov, M06 12 Nov, M09 6 Nov 2026. (10) skip supply rows for commodities whose unit is not `RM/kg` (Telur Gred A), so `supplyConfirm` returns `tiada` and the P3 row never turns red; P3 row note "Telur: bekalan dalam unit lain, tidak dinilai".

## Keputusan reka bentuk (ringkas)

- **No FEAT decomposition / no workflow restructure.** The work is one HTML file and one IIFE (`#ivScript`) with a shared `ivState`; panels depend on one another (P1 dispatches, P2 to P6 read), so splitting into separate coder steps would race on the same file. The existing implement-and-review loop runs this plan unchanged.
- **Second MapLibre instance** on `#ivMap`, same library, style URL and bounds as the existing map (B1 option b), created lazily on first show. Existing map code is closure-private, so sharing it is unsafe.
- **Tab bar with `#viewMonitor` wrapper** around existing content (E2/E3) rather than a separate page; old ids and classes are untouched.
- **Isolation:** one strict-mode IIFE; only added `window` keys are `FAMA_MAP_CONFIG`, `IV_TEST`, `famaMonitorMapResize`, `famaScenariosReady`.
- **Rules from the design are adopted as written** (B5.1 thresholds in one config object, B5.2 directional level, B5.4 price alone never critical, B5.5 score, B5.6 engine, B5.7 district/zone, B5.8 margin, B5.9 Muse, B5.10 filters), with the Keputusan above overriding.
